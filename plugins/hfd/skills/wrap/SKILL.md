# /hfd:wrap

세션을 닫는다. 목표는 **다음 세션이 이 대화 없이도 바로 이어서 일할 수 있게** 만드는 것이다.
쓰기만 하지 않는다 — **옮기고, 고치고, 비우고, 검사한다.**
파일을 어디에 두고 어떻게 등록하는지는 하네스 규칙 세트의 자리표를 따른다: `${CLAUDE_PLUGIN_ROOT}/skills/harness/references/placement.md`

## 인자

- 없음: 전체 수행 (0~11단계)
- `quick`: 1b·1d·8 생략. 나머지 전부 수행. **9단계 검사 게이트는 생략 불가.**
- 이번 세션에 바뀐 파일이 하나도 없으면 "변경 사항 없음. 정리할 것이 없습니다."로 끝낸다.

## 공통 규칙

- **제한(줄 수·개수)을 맞추려고 내용을 지우지 않는다.** 넘치는 건 원문 그대로 `docs/archive/`로 옮기고, 옮긴 경로를 남은 파일과 보고에 적는다. 지워도 되는 건 `[x]` 완료 항목과, 다른 파일에 이미 같은 내용이 있는 중복뿐.
- **이번 세션과 무관하게 예전부터 쌓인 문제**(오래된 긴 HANDOFF, 수십 줄 현재 상태, 문서 지도가 아직 없는 옛 프로젝트 등)로 9단계가 FAIL이면: 옮길 양이 적으면 archive로 옮겨 정리하고, 구조를 크게 바꿔야 하면(날짜 로그가 섞인 CHANGELOG 등) **멈추고 사용자에게 "대청소가 필요하다 — 지금 할지"를 묻는다.** 묻지 않고 대규모로 뜯어고치지 않는다.

- CHANGELOG.md·MEMORY.md에는 Write 금지, **Edit만** (다른 부분 보존).
- 시크릿 값·환경변수 값은 어디에도 적지 않는다. 이름·위치만.
- `.codex/HANDOFF.md` 등 다른 에이전트 파일은 사용자가 요청하지 않는 한 읽지도 고치지도 않는다.
- 사용자 되묻기는 꼭 필요한 곳(4단계 날짜 로그 처리, 8단계 승급, 10단계 main push)에서만.

## 0. 대상 확정

1. **작업 폴더 목록** = 이번 세션에서 실제로 파일을 만들거나 고친 프로젝트. 열린 폴더가 아니다.
   판정: 대화에 나온 Write/Edit 경로 + 각 후보에서 `git status --short`. 프로젝트 루트 = 그 경로 위쪽에서
   `CHANGELOG.md`·`CLAUDE.md`·`.git` 중 하나가 있는 가장 가까운 폴더.
2. 프로젝트마다 확정해 적어 둔다:
   - **메모리 폴더**: `<프로젝트>/.claude/settings.local.json`의 `autoMemoryDirectory`(`~`는 `$HOME`으로 확장)
     → 없으면 `~/.claude/projects/<절대경로의 영숫자 아닌 글자를 전부 '-'로 바꾼 이름>/memory/`
     (예: `/Users/a/★ A.I/x_y` → `-Users-a---A-I-x-y`. 한글도 한 글자당 `-` 하나, 경로는 NFC로 맞춘 뒤 계산).
     **계산한 폴더가 실제로 있는지 `ls -d`로 확인한다.** 없으면 `ls ~/.claude/projects | grep <프로젝트명 영문 조각>`으로
     실제 폴더를 찾아 쓴다. 그래도 없을 때만 새로 만든다(엉뚱한 새 폴더에 쓰지 않기 위해).
   - git 저장소인지(`git rev-parse --show-toplevel`), 원격 있는지(`git remote -v`), 현재 브랜치.
3. 열린 폴더 ≠ 작업 폴더면 **기록은 작업 폴더에만** 쓴다. 열린 폴더 쪽 파일은 건드리지 않고,
   필요하면 보고에 "기록은 <작업 폴더>에 남김" 한 줄만 적는다.
4. 결과를 한 번 출력한다:
   ```
   대상: <작업 폴더> | 메모리: <폴더> | git: 예/아니오 · 원격: 있음/없음 · 브랜치: <이름>
   ```

## 1. 대화에만 있는 것 수거

대화 전체를 훑어 아래 네 종류를 **목록으로** 만든 뒤 하나씩 파일로 옮긴다. 목록에 없는 건 다음 세션이 모른다.
대화가 압축돼 앞부분이 요약만 남았으면, 세션 원본 기록 `~/.claude/projects/<열린 폴더 변환 이름>/<세션ID>.jsonl`에서
사용자 입력(`"type":"user"`)과 조사 도구 결과를 확인한다. 요약만 보고 옮기지 않는다.

**a) 조사 결론** (웹·문서·코드 조사) → `docs/research/<주제>.md`
```markdown
# <주제> — 조사 완료, 재조사 금지 (YYYY-MM-DD)
| 질문 | 결론 | 출처 |
|---|---|---|
## 핵심 원문 인용
> "..." — <URL>
## 남은 미확인 → 실험으로 확정
- <조사로는 더 안 나오고 직접 해 봐야 하는 것>
```
이미 같은 주제 파일이 있으면 새로 만들지 말고 그 파일을 고친다.

**b) 결정과 이유 + 사용자 지시 원문** → 해당 트랙 문서(계획서·STATUS 등) 또는 `docs/decisions/<날짜>-<주제>.md`.
형식: `결정 / 이유 / 사용자 원문: "…"(한두 문장 인용) / 날짜`.

**c) 앞으로 매번 해야 하는 규칙** → 사건 문장이 아니라 **체크리스트**로 적는다.
위치: 프로젝트 `CLAUDE.md`의 「체크리스트」 칸, 또는 메모리 project 파일의 `## 체크리스트` 칸.
- ✗ "0.4.2로 틀 zip 재생성함" (사건 — 다음 버전 때 안 읽힘)
- ✓ "- [ ] 플러그인 버전 올릴 때: 틀 zip 재생성 → 가이드 재빌드 → 배포" (규칙)

**d) 저장소 밖 산출물·맥락** (Downloads 파일, 배포 URL, 서버, Codex 작업, 다른 저장소 커밋)
→ 메모리 `reference_<slug>.md`로 위치를 등록(7단계 형식).

수거 결과를 출력: `수거: 조사 N · 결정 N · 규칙 N · 바깥 N (각 저장 경로)`.

## 2. 옛 사실 고치기

이번 세션에서 **확정되거나 정정된 사실**마다:
1. 핵심 단어 2~3개로 grep: 메모리 폴더 전체, `.claude/HANDOFF.md`, CHANGELOG 「현재 상태」, 프로젝트 `CLAUDE.md`.
2. 새 사실과 어긋나는 문장은 **그 자리에서 고치거나 지운다. 아래에 덧붙이지 않는다.**
   (옛 문장이 남아 있으면 다음 세션이 둘 중 아무거나 믿는다.)
3. 같은 메모리가 여러 폴더에 사본으로 있으면 정본 하나만 남기고 나머지는
   `정본: <경로>` 한 줄 포인터로 바꾼다.

출력: `정정: <파일:줄> 옛 → 새` 목록 (없으면 "정정 없음").

## 3. 문서 지도 정리

이번 세션에 만들거나 옮긴 문서·폴더를 **지도 3층**에 등록한다 (`placement.md` 5절).
- `docs/` 아래 새 문서 → 그 폴더의 `index.md`에 한 줄. 새 폴더면 `index.md`를 만들고 상위 index에 한 줄.
- 루트에 새로 만든 폴더·주요 파일 → `CLAUDE.md` 「파일 맵」에 한 줄.
- 옮기거나 지운 문서 → index의 줄도 고치거나 지운다 (깨진 링크를 남기지 않는다).
- 형식: `- [이름](경로) — 한 줄 설명`.
- 새 폴더를 만든 것 자체는 문제가 아니다. 막지 않는다. 등록만 한다.

출력: `지도: 등록 N · 수정 N · 새 index N (파일 목록)`.

## 4. CHANGELOG 「현재 상태」

`## 현재 상태` 다음 줄부터 다음 `## ` 제목 **직전까지**를 Edit로 **덮어쓴다**. 15줄 이하.
```markdown
## 현재 상태
<!-- /wrap이 매 세션 덮어씀. 15줄 이하. 옛 내용은 docs/archive/changelog-current-state-*.md -->
**진입점:** 다음 할 일 = `.claude/HANDOFF.md` · 옛 상태 = `docs/archive/`

| 트랙 | 상태 (YYYY-MM-DD) | 어디 (파일·URL·커밋) |
|---|---|---|
| <트랙> | <한 줄> | <경로> |
```
- 한 칸은 한 줄, 한 행 400자 이하. 설명은 파일로 보내고 여기엔 경로만.
- 넘치거나 끝난 트랙은 원문 그대로 `docs/archive/changelog-current-state-<YYYY-MM-DD>.md`로 옮긴 뒤 표에서 뺀다.
- 교체 범위 안에 날짜 로그(`### YYYY-MM-DD` 등)가 섞여 있으면 **지우지 말고 멈춘다.**
  사용자에게 "현재 상태 칸에 날짜 로그 N개가 있다. 세션 로그로 옮길까?"를 묻고 답에 따른다.
- CHANGELOG가 없으면 아래 틀로 만든다(이때만 Write 허용):
  ```markdown
  # Changelog

  ## 현재 상태
  <!-- /wrap이 매 세션 덮어씀. 15줄 이하. -->
  | 트랙 | 상태 | 어디 |
  |---|---|---|

  ## 세션 로그
  <!-- ⚠️ APPEND ONLY — 아래 항목을 절대 삭제/수정하지 마세요. 새 항목은 이 줄 바로 아래에 추가합니다. -->
  ```

## 5. HANDOFF — 다음 세션이 할 일만

파일: `<작업 폴더>/.claude/HANDOFF.md`. 기존 파일은 **Read 후 트랙 단위로 갱신**(이번에 안 건드린 트랙은 그대로 둔다).
```markdown
# HANDOFF
updated: YYYY-MM-DD HH:MM

## <트랙명>
- [ ] <할 일 1 — 다음 세션 시작점>
- [ ] <할 일 2>
**확정·재조사 금지:** (≤5줄)
- <확정 사실> — 근거 `<파일>`
**필독:** `<경로>`, `<경로>`
```
- 트랙당 할 일 ≤5개. 첫 번째가 시작점.
- **완료(`[x]`) 항목과 끝난 트랙은 삭제한다.** 기록이 필요하면 `docs/archive/`로. 완료 이력은 세션 로그가 맡는다.
- 전체 80줄 이하. 넘으면 설명을 문서로 빼고 경로만 남긴다.
- 모든 트랙에 할 일이 없으면 파일을 삭제한다(`rm -f .claude/HANDOFF.md`).
- `.gitignore`에 `.claude/HANDOFF.md`가 없고 git 저장소면 추가한다.

## 6. 세션 로그

`<!-- ⚠️ APPEND ONLY … -->` 주석 **바로 아래**에 세션당 항목 1개를 넣는다.
```markdown
### YYYY-MM-DD — <세션 제목>
- <무엇을 했나 1~3줄, 결과물 경로 포함>
```
- 같은 세션에서 두 번째 wrap이면 새 항목을 만들지 말고 **이번 세션 항목을 고친다.**
- 이전 세션 항목은 수정·삭제 금지.
- 주석이 `## 세션 로그` 제목에서 멀리 떨어져 있으면(5줄 초과) 주석을 제목 바로 아래로 옮긴다(항목 순서는 유지).

## 7. 메모리

**0단계에서 정한 메모리 폴더에만** 쓴다. 다른 폴더에 사본을 만들지 않는다.
- `MEMORY.md`는 Edit로. 200줄 이하. 목차의 링크가 전부 실제 파일을 가리키게.
- 새 산출물·바깥 위치(1d)는 `reference_<slug>.md`로 등록:
  ```markdown
  ---
  name: <산출물 이름>
  description: <한 줄 + 동의어 키워드 — "대시보드", "링크", "장표", "가이드" 등 사용자가 찾을 때 쓸 말>
  type: reference
  ---
  경로/URL: <위치>
  무엇: <어떤 작업의 결과인지 1~2줄>
  여는 법: <open 경로 / 브라우저 / gh repo clone …>
  ```
  목차에 한 줄: `- [<이름>](reference_<slug>.md) — <위치 + 용도>`
- frontmatter는 첫 줄 `---`, 닫는 `---`까지 키: 값만. 사이에 표(`|`)·본문을 넣지 않는다.
- 끝난 워크스트림은 목차에서 한 줄 요약으로 줄이거나 지운다(내용은 토픽 파일로 옮긴 뒤).

## 8. 교훈 (최대 2개) + 장치 승급 제안

- `Retros/LESSONS.md`의 주제별 `## <주제>` 아래에 넣는다(없으면 주제 섹션 생성):
  ```markdown
  ### <짧은 제목> #coding|#strategy|#both #<주제-태그>
  <구체적 교훈 1~3줄. 실제 사건 한 구절 포함.>
  ```
  다음 세션 시작 때 파일 상단부터 40개가 자동 주입된다(태그 무관). 새 교훈은 해당 주제 섹션 **맨 위**에. 태그는 소문자-하이픈.
- 사용자에게 교훈 후보를 보여주고 확정받는다. 거절하면 넘어간다.
- **승급 후보 찾기**: 이 프로젝트의 `Retros/LESSONS.md`와 이번 세션 대화에서 **같은 실수·같은 요청이 반복된 것**을 찾는다
  (같은 태그의 교훈 2개 이상, 같은 교정을 두 번 받음, 같은 절차를 세 번째 붙여넣음 등).
- **어떤 장치로 올릴지**는 하네스 방법론 2절의 공식 표를 따른다:
  `${CLAUDE_PLUGIN_ROOT}/skills/harness/references/methodology.md` 2절
  (예: 같은 규칙을 두 번 틀림 → `CLAUDE.md`에 추가 / 매번 자동으로 일어나야 함 → 훅 / 같은 절차를 세 번째 붙여넣음 → 스킬)
  `CLAUDE.md`로 올리는 규칙은 「하지 않는 것」 또는 「체크리스트」 칸에 넣는다.
- 후보마다 "반복된 것 → 표의 해당 줄 → 올릴 자리"를 한 줄로 보여주고 사용자에게 묻는다.
  **적용은 제안만(HITL).** 자동으로 CLAUDE.md·settings·훅을 고치지 않는다. 한 번에 최대 3개.

## 9. 자동 검사 (필수 게이트) — 커밋 전에

작업 폴더마다 실행한다:
```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/harness/scripts/harness_check.py" --project "<작업 폴더>" --memory "<메모리 폴더>" \
  --keywords "<이번 세션 핵심어1>,<핵심어2>,<핵심어3>"
```
- 키워드 = 다음 세션 사용자가 찾을 때 쓸 말(트랙명·산출물명·도구명). 3~6개.
- 키워드가 **옛 파일에서만** 걸리면 WARN이 뜬다 → 이번 세션 결론이 실제로 파일에 들어갔는지 다시 본다.
- **FAIL이 하나라도 있으면 고치고 다시 실행한다.** PASS 전에는 "정리 완료"라고 말하지 않는다.
- WARN은 보고에 적고 넘어가도 된다.
- 윈도우에서 `python3`가 없으면 `python` 또는 `py -3`로 실행한다. 파이썬이 아예 없으면 `/hfd:setup`을 안내한다.
- 검사에는 기존 항목(HANDOFF·CHANGELOG·메모리·키워드)과 하네스 항목(`CLAUDE.md` 200줄·파일 맵, 문서 지도, 기획 문서 필수 칸)이 함께 있다.
- **검사를 고친 뒤 커밋한다.** 커밋 뒤에 고치면 그 수정이 커밋에서 빠진다.
- 결과 표를 그대로 사용자에게 보여준다.

## 10. 커밋 — 검사 통과 후

- git 저장소가 아니면: "git 아님 — 커밋 생략" 알리고 넘어간다.
- 저장소면: `git status`로 확인 → **이번 세션 파일만 경로를 적어** `git add <경로…>`.
  `git add -A`·`git add .` 금지. `.env*`·`*secret*`·`*key*`·`scripts/`가 스테이징에 보이면 멈추고 보고.
- 커밋 메시지 = 세션 요약 한 줄 + 필요시 본문.
- 원격이 없으면 push 생략하고 "원격 없음 — 이 맥에만 있음"을 알린다.
- 현재 브랜치가 `main`/`master`면 **push 전에 묻는다**(기능 브랜치 제안).
